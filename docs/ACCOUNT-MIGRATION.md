# ACCOUNT MIGRATION — 干净 Profile 与正式账户切换

本文件只描述操作顺序与每步是否改变数据。所有真实写入由本人执行。

## 0. 准备

1. 关闭其他会写同一 Profile 的窗口。
2. 在 Wealthfolio 中备份当前资料库（官方备份功能）。**会创建备份文件，不改数据。**
3. 保留旧验收 Profile，不删除、不覆盖。**不改数据。**

## 1. 创建干净正式 Profile

1. 用客户端官方 Profile 功能新建一个 Profile。**会创建新数据库，不影响旧 Profile。**
2. 在新 Profile 中确认：没有 WRISK/WRISKDEMO 账户、没有旧测试成本、没有旧插件授权。
3. 不要复制旧 Profile 的数据库文件来“迁移”，也不要用 WF_* 环境变量改桌面安装。

## 2. 安装与连接

1. 安装 `wealthfolio-binance-risk-0.4.0.zip`；页脚核对 `0.4.0` 与指纹前缀（见构建回执）。
2. 打开插件 → 连接设置 → 输入新只读账户的 UID/Key/Secret。**凭据只由本人在本机输入。**
3. 完成四项确认 → 首次查询。**会读取余额；不写原生账本。**
4. 核对数量与 UID；如换账户（UID 不同），不继承旧绑定、旧成本、旧预览。

## 3. 汇率与成本

1. 在「原生同步」点“检测宿主能力”。确认 `USDT → 基础货币` 显示有效（按日期或最新记录）。
2. 若显示“未找到记录/权限不足”，先处理汇率或权限；不要继续写入。
3. 在成本表按**单位成本（USDT）**录入，表格实时显示“数量 × 单位成本 = 总成本”。
4. 核对后点“确认全部成本”。未确认的填写只显示“待确认”，不称“已核实”。
5. 成本保存在本机插件存储 `native-costs-v1`（不含密钥）。

## 4. 首次导入

1. 点“生成导入预览”。**不写入。**
2. 核对：目标账户、快照日期、持仓数、USDT 现金、已定价小计、预计基础货币总额、成本缺失项。
3. 若提示 `MISSING_COST`：补成本；生产版本不提供“忽略成本”旁路。
4. 勾选确认 → “写入原生账户”。**会创建/绑定账户、写当日快照、切资产为 MANUAL、写市场报价。**
5. 查看结果状态：
   - `已对账`：数量读回一致，报价与模式成功。
   - `持仓已写入 · 报价待修复`：点“仅修复报价”，不要重复写快照。
   - `已提交 · 未读回`：到原生账户页核对，不要重建账户。

## 5. 原生页核对

1. 账户类型为 CRYPTOCURRENCY、追踪模式 HOLDINGS、币种 USDT。
2. 持仓数量 = free + locked；USDT 只出现在现金，不重复为持仓。
3. 成本与盈亏来自已确认的 `averageCost`；未知成本的资产不应存在。
4. 基础货币总额按宿主汇率换算；USDT 现金可能按 1:1 计入（宿主日期汇率限制），需单独核对。
5. 历史/绩效指标在只有一个估值点时为 N/A，属正常。

## 6. 重复与日常

1. 同日再同步：覆盖当日快照，不新增账户/资产。
2. 新一天同步：新增当日快照。
3. 修改成本：重新预览 → 写入；同日覆盖。
4. 当前**没有后台自动同步**；离开插件页后不会继续。需要更新时回到插件手动同步。

## 7. 回退

1. 停止使用：插件“断开连接”（不删除原生账户）。
2. 需要撤销本次导入：在原生 UI 手动删除该账户或当日快照；插件不提供删除 API 权限。
3. 恢复旧 Profile：用第 0 步的备份；不要覆盖新 Profile。
4. 卸载插件不会撤销币安密钥，也不会删除原生账户。

## 8. 切换账户

- **只换 Binance 账户（UID 不同）**：断开 → 清空旧成本（或保留但不再使用）→ 新 UID 查询 → 新预览 → 新绑定。旧原生账户保留，不自动删除。
- **只换 Profile**：新 Profile 中重新安装/授权；旧 Profile 的 storage、secrets、原生账户不迁移。
- 两种切换都不要复制旧授权状态或旧预览。
