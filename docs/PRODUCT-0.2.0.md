## 报价路径与刷新设计

- 公开请求仅官方network.request → data-api.binance.vision；只传所需资产交易对，不传凭据、UID或数量。
- 从资产生成有限候选，但必须经exchangeInfo明确baseAsset、quoteAsset=USDT、TRADING、isSpotTradingAllowed校验。不是截ticker字符串猜身份。
- exchangeInfo使用showPermissionSets=false减小响应；有效映射缓存15分钟，明确无市场缓存3分钟；网络错误不缓存。ticker额外要求symbolStatus=TRADING，避免缓存期间停牌仍被报价。
- 每20个交易对一批；-1121逐项隔离，其他故障不擅自增加替代主机。2MiB响应、64KiB错误正文、15秒插件计时器及SDK10秒超时保持。
- 成功连接后公开行情默认每60秒刷新；余额默认手动，数量对账后本人可启用每300秒余额同步。一个调度器、全局单飞，余额到期优先。
- 行情失败按120/240/300秒退避；余额原10/20/30分钟退避保持。429/418共享Retry-After冷却；迟到限流保留；在途SDK未结束不会重试。
- 页面隐藏暂停，返回可见后补查；断开停止所有新请求及迟到发布。成功后的公开刷新不读secrets；认证查询仍由既有本人确认或本人开启的余额自动刷新控制。
- 余额有效期6分钟，行情2分钟；未来时间仍拒绝。USDT单位价格无需市场TTL，但USDT数量仍受余额时效约束。
- 缺价/失败不算零。无当前合计时显示上次估值及时间/当时覆盖；行内历史市值标记“历史”，详情列出当时数量和时间。历史值从不进入当前总值、配置或压力分析。
- 最近完整估值优先保留；尚无完整估值时保留最近可估值部分。并非持久化历史曲线，退出插件会话不保证保存。
- 微额仅以当前可靠市值<0.1 USDT折叠；仍计总值和配置。历史或缺价资产不隐藏。配置分母是当前已估值范围，部分覆盖醒目标明。
- 当前只覆盖可验证直接USDT交易对。不实施反向/跨币种多跳、停牌价推断或未知资产猜价；没有市场的资产继续明确缺价。

## 成本与盈亏阶段方案

官方myTrades需要symbol，默认最近500笔、最多1000笔；fromId分页，起止时间窗口最多24小时。不能用一次查询证明成本完整，也不能仅从当前持仓推断全部曾交易市场。

本轮阶段0：平均成本“未核实”，累计盈亏百分比/金额均为“—”。没有myTrades请求构造、权限或发送路径。稳定币同样不被假定零成本，也不使用24小时涨跌幅代替持仓收益。

下一阶段拟采用FIFO剩余批次成本（不是税务结论），须先独立审查和虚构验证，再取得本人新增签名读取确认：

1. 市场清单与历史完整性：已退市/非USDT历史市场、分页游标、重复成交ID、缺页、同毫秒顺序均核实；不能把“分页结束”直接当账户完整历史。
2. 买入费用：base手续费减少收到数量；quote手续费加入成本；第三币手续费扣减该币批次，需成交时的可靠汇率和手续费成本归属。未知费用币或汇率阻断对应成本。
3. 部分卖出：消费FIFO批次，剩余单位成本不能因卖出收入而重置；卖出手续费属于已实现部分，不重复加进剩余持仓。
4. 转入/转出/内部划转、Convert、奖励、空投、拆并币等造成的余额差额必须有来源；myTrades不是转入成本凭证。未知来源只允许标记未知批次，不填零。
5. 将重建剩余数量与同一账户Spot快照逐项对账；禁止未来成交混入旧快照。成交到余额之间无法确认的并发变化显示待核对。
6. 已确认成本范围盈亏=该范围当前市值−剩余成本；收益率=该盈亏/正的剩余成本。稳定币在成本可靠时参与；零分母、缺价或成本缺口不给全账户率。数量覆盖与市值覆盖分别标注。

必须先通过的虚构案例：买2单位各100、200并卖1.5后FIFO剩余成本100；转入1单位未知来源不并入收益率分母；base/quote/第三币手续费各自守恒；分页重复不重复计成本，缺页拒绝；稳定币脱锚使用市场价格；部分确认成本只给部分收益。

## 产品信息架构与视觉

- 主页面：账户状态、简洁操作、资产总值、成本覆盖、余额时间、四列持仓和配置条。
- 点击资产：当前/历史数量、价格、市值、成本占位、报价来源和采集时间；原生dialog支持Escape、焦点约束与返回。
- 风险：独立页签；非USDT统一-20%情景包含其他稳定币，明确不是预测，不冒充完整账户风险。
- 开发：从连接设置单独进入；不在正式首页挂载模拟面板/备用读取器。旧风险、模拟备份及离线验证能力保留。
- 深色中性背景、克制蓝灰/绿灰配色、数字等宽排版；宽窗口两栏，窄窗口堆叠；样式全部限定.wrisk-app，不修改宿主主题。

参考[TradingView持仓定义](https://www.tradingview.com/support/solutions/43000756132-holdings-page/)的持仓/成本/风险分层与无成本时“—”，以及[配置视图](https://www.tradingview.com/support/solutions/43000756102-overview-portfolio-distribution/)的价值与占比关系；不复制行情涨跌作为账户盈亏。

## 安全和能力边界

官方secrets、双槽生命周期、签名、只读危险权限校验、UID、小额不强制IP策略均保持。两个主机与两个私人GET路径未扩大；没有fetch/localhost生产代理/宿主写入/AI调用/新增依赖。预览仅本机静态虚构页面，transport为内存函数，未接宿主。

宿主签名URL错误日志剩余风险仍存在，用户此前已接受；本轮没有修改宿主、代理、TLS或AI配置。历史参考和市场缓存仅会话内存，不能进模拟备份。

GitHub API本轮确认仓库当前为公开；旧文档的Private不是现状。不修改可见性；只提交可公开源码、虚构测试和脱敏文档，产物与截图留本地。
