# v0.3.1 原生集成深度验收

本版不增加功能，只把 0.3.0 的原生写入变成可反复同步、异常可恢复、成本口径不会被伪造的连接器。
**真实宿主写入仍未执行**；以下结论来自 SDK 3.9.0 类型、Wealthfolio v3.10.0 Rust 源码与虚构宿主。

## 一、宿主估值路径（源码结论）

`crates/core/src/portfolio/holdings/holdings_valuation_service.rs`：

| 事实 | 后果 |
|---|---|
| 证券市值 = `quote.close × quantity × 合约乘数`，再按**报价货币**换算到账户货币与基础货币 | 报价币种必须与 `quoteCcy` 一致；我们统一 USDT |
| 现金价格固定为 1，`cost_basis = 市值`，全部收益字段为 0 | USDT 现金不产生盈亏，符合我们的成本口径 |
| 报价缺失 → `market_value = 0`，价格与收益字段清空，只记一条 warn | **报价写入失败的资产在原生页面按 0 计**；必须明确告知 |
| 汇率缺失 → `get_fx_rate_or_fallback` 回退 `Decimal::ONE`，只记 warn | 原生可能把 1 USDT 当 1 USD；插件在预览阶段阻断，但不能控制宿主后续读取 |
| 没有报价过期判断，始终使用最新一条 | 原生页面是"最后推送的报价"，不是实时行情；实时视图仍以插件为准 |
| 未实现盈亏 = `market_value − cost_basis`；`cost_basis` 来自 Position，不由均价重算 | `averageCost` 必须可靠；缺失时宿主按 0 处理，等于把全部市值算成收益 |
| 账户货币 = 基础货币没有特判 | 同币种也走 FX 查询；USDT 账户仍依赖 USDT→USD 汇率 |

## 二、本版新增的安全门槛

1. **成本门槛**：任一持仓没有已核实单位成本时，预览默认阻断（`MISSING_COST`），因为宿主会把缺失成本当 0。
   用户可勾选"允许这些资产仅导入数量"，此时预览明确列出资产并声明原生盈亏不可用；不勾选则无法写入。
2. **账户类型门槛**：绑定账户必须是 `CRYPTOCURRENCY` + `HOLDINGS`，否则阻断（`ACCOUNT_MISMATCH`），不写入交易模式账户。
3. **持久绑定**：创建账户后把 id 写入插件 storage（`native-account-<哈希>`）。用户改名、宿主丢弃 provider 字段后仍能找回同一账户，不再新建。
4. **读回失败不丢结果**：快照提交后读回失败时，返回"已提交 · 未读回"而不是抛错；不重试、不重建账户，提示本人核对。
5. **报价失败明示后果**：报价写入失败会计数并提示"原生页面会把这些资产按 0 估值"，不回滚已写入的持仓。
6. **全局报价提示**：报价按资产写入，可能影响其他账户中同一资产的估值；MANUAL 资产跳过。

## 三、验收矩阵（虚构宿主）

| 场景 | 结果 |
|---|---|
| 创建 CRYPTOCURRENCY/HOLDINGS 账户 | 通过（替身） |
| 写入 BTC/ETH/BNB/USDC + USDT 现金 | 通过；USDT 进 `cashBalances` |
| 资产身份 `CRYPTO:SYMBOL/USDT` | 通过；同身份复用 |
| 连续同步两次 | 第二次绑定，不重复建账户/资产 |
| 同日数据变化再同步 | 同一日期覆盖，不累加 |
| 用户改名/宿主丢 provider | 通过持久绑定找回 |
| 账户被改成 TRANSACTIONS | 阻断 |
| 创建成功、写快照失败 | 账户保留；重试绑定后成功，不重复创建 |
| 写快照成功、读回失败 | 返回"未读回"，不重试不重建 |
| 报价部分失败 | 持仓保留，提示按 0 估值 |
| 汇率缺失 | 预览阻断 |
| 成本部分缺失 | 默认阻断；显式允许后写入并声明盈亏不可用 |
| 重复点击写入 | 按钮 busy 禁用；同日覆盖幂等 |
| 原生总资产 vs 插件估值 | 未在真实宿主核对；预览给出"按当前汇率预计基础货币总额" |

## 四、成本可信度

- 单位成本以 USDT 计，`averageCost × quantity = total_cost_basis`，与宿主公式一致。
- USDT 现金成本等于市值，盈亏恒为 0。
- 插件 Hero：未录入 → 成本尚未核实；部分 → 仅已核实成本部分；完整 → 持仓累计盈亏。分母是已核实成本，不是全部市值。
- 原生账户：只有在全部持仓成本已核实（或用户显式接受未知成本）时，原生盈亏才可被引用。
- 修改成本会改变预览指纹，必须重新预览；同日重写覆盖旧快照，宿主重新计算。
- 撤销：清除输入后重新同步（成本回到未知，默认阻断），或在原生 UI 手动修正。

## 五、残余风险

1. 宿主在读取时若丢失 USDT→USD 汇率，会静默按 1.0 计算；插件无法拦截，只能提示并依赖用户维护汇率。
2. 原生报价没有 TTL；不同步就不会更新。
3. 首次导入前无法 `checkImport`（需要已存在账户），符号解析由宿主在写入时完成。
4. 报价按资产全局生效，可能影响其他账户。
5. `Holding.quantity` 是浮点，读回对账使用 1e-12 相对容差。
6. `Quote.close` 是 number，极大数值会丢精度（加密价格范围内无实际影响）。
