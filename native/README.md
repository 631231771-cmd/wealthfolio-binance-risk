# Windows 本地 Spot 只读读取器

v0.1.8；使用Windows自带.NET Framework/C#编译器、WinForms、DPAPI及HttpClient，无第三方依赖或监听服务。只支持HMAC Key/Secret和单个预期Binance UID，不支持RSA/Ed25519、Funding或Stocks。

## 当前验收方式

1. 打开项目 `artifacts/spot-reader/WealthfolioSpotReader.exe`，默认是**虚构验收模式**，不发送认证请求；不要在此模式输入真实密钥。
2. UID使用900000001，输入明确虚构的Key/Secret，点击“安全保存／替换凭据”。输入框清空；重启同一程序应显示已保存，但不会自动请求。改用第二组虚构值保存可检查替换。
3. 点击“读取并生成余额快照”，生成BTC0.001、ETH0.02、USDT15、NOPAIR2，模式fixture。只选中下方快照框内容、复制到插件“本地读取器余额”入口。不要复制输入密钥。
4. 60秒内导入；点击插件“更新公开报价并估值”，只读已批准的公开主机。BTC/ETH使用实际USDT价格；USDT按同币单位；NOPAIR保留缺价、完整Spot总额不可用；金额随市场变化。
5. 重复导入不累加；过期后当前不可用；首次失败没有历史零。读取失败时，必须将辅助程序生成的failed快照导入；如缺凭据等导致没有快照，在插件空输入框点击导入，会使当前数据失效。完全不交接失败状态，则旧余额最多在60秒有效期内仍可能显示，插件不会知道辅助程序刚失败。
6. 点击辅助程序“断开并删除本机凭据”，确认后状态应为空。此操作不会撤销币安端Key，也不会更改Wealthfolio的secrets。关闭读取器取消在途请求，默认没有后台运行。

## 真实模式的下一轮授权

当前只完成虚构验收。未经用户下一次明确确认，不启动真实认证。真实模式只有显式参数`--allow-live`才能打开，还必须在界面勾选真实只读确认并主动点击读取；默认程序从不自动切换。两种模式使用独立加密目录，WRISK_虚构凭据不能用于真实模式。首次真实操作交由用户亲自输入，禁止在聊天或工具参数提供Key/Secret。

确认后，用户在**独立几千元测试账户**的币安官方API管理创建系统生成HMAC密钥，仅保留读取，关闭交易/杠杆/合约/提现/划转等授权；根据实际请求出口设置IP限制。先核对该账户UID并填写预期UID；不要使用主账户密钥。账户接口的canTrade等返回字段不能证明API Key只有读取权限，必须人工核对权限页。密钥输入辅助程序的本机密码框，不输入插件、聊天、DeepSeek、命令行或环境变量；保存后清空输入，第一次请求仍需用户明确批准。支持范围仅Spot余额，不推断其他账户是否为空。

## 存储、日志与隐私边界

- 凭据对使用DPAPI CurrentUser加密，位于`%LOCALAPPDATA%/WealthfolioBinanceRisk/spot-fixture`或`spot-live`中的credentials.dpapi；先写候选、解密校验，再同卷原子替换。临时文件仍是密文；删除失败不能宣称清理成功。不要将目录纳入Git或云盘。
- Windows用户级加密不防同用户恶意进程、调试器或管理员。输入及签名期间凭据会短暂存在本程序内存；不宣称字符串可被可靠清零。凭据文件不是跨机器备份；停用Key还须在币安端撤销。
- 真实网络只构造HTTPS api.binance.com的GET time/account；拒绝重定向，启用系统证书验证，不配置自签名信任、直连绕过或第三方代理。使用系统现有代理设置时，IP限制应与实际出口相符。没有API可配置URL、header或任意路径。
- 程序不写HTTP日志，不输出原异常、header、完整URL或响应body；界面只显示固定错误码。正常错误仍可见，不关闭宿主日志。超时/断开/429/418无自动重试，限流须冷却后手动操作。操作系统网络追踪、崩溃转储、恶意进程不属于本程序日志保护承诺。
- 余额快照仅白名单资产/数量/UID/采集起止/状态；没有凭据，但属于财务隐私。请避免云剪贴板/云盘、聊天上传和遗留副本。快照未做来源签名，插件验证格式、账户及时间，不能证明用户未编辑内容。插件状态仅页面内存，不写宿主投资组合，因此不授权内置AI读取真实资产；仍须在首次真实测试前由用户核实独立资料库AI隔离，不能宣称已经验证DeepSeek隔离。

## 开发与验证

`npm run verify`包括96项TypeScript测试、类型/插件构建/ZIP/静态入口，以及本机C#编译、DPAPI独立进程生命周期、原生loopback HTTP签名/错误测试与快照到插件解析。自检只在临时loopback服务器使用固定假凭据，绝不通过Wealthfolio代理或Binance私人主机；测试输出明确fixture。构建产物及记录在artifacts/spot-reader，全部被Git忽略。原生TLS握手故障/实际Binance认证和API Key权限没有实测，不能用这些测试冒充通过。
